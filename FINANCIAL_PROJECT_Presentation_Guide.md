### 🎯 Key Viva Defense Answers for Your Panel:

#### Q1: "Why use an on-premise TinyLlama 1.1B LLM rather than external APIs like OpenAI GPT-4?"
> *"In financial systems, user data privacy, regulatory compliance (such as RBI and SEBI data localization guidelines), and operational economics are critical. Sending sensitive salary details, expense records, and net worth figures to external third-party cloud APIs introduces compliance and privacy risks. By running TinyLlama 1.1B locally on port 5002, data remains within the local perimeter, inference latency stays under one second without third-party network round-trips, and the platform incurs zero recurring per-token API costs."*

#### Q2: "How is sensitive payment information protected in your database?"
> *"We follow a defense-in-depth model:  
> 1. Passwords are salted and hashed using Bcrypt with 12 computational rounds.  
> 2. Card numbers and CVVs are encrypted at rest using a dedicated symmetric key (`CARD_ENC_KEY`) before saving to MongoDB.  
> 3. The frontend displays masked card digits by default; unmasking requires biometric or credential re-authentication via the `/api/cards/:cardId/reveal` endpoint.  
> 4. All API routes are protected by stateless JWT bearer tokens with 8-hour expiration windows and strict CORS origin verification."*

#### Q3: "How does the platform maintain responsiveness during real-time video sessions and market price streaming?"
> *"Real-time collaboration runs over dedicated Socket.io WebSockets using room-based multiplexing directly in memory, ensuring that video signaling and chat messages never block the database thread. Messages are written to MongoDB asynchronously. For external market quotes and metal spot prices, responses are cached with HTTP `Cache-Control` headers to prevent redundant network requests, while Express rate limiting protects the gateway from request saturation."*
